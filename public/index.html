Selected work

Six problems, what I did, and what changed

01 / 06

The consent manager was missing from almost every page view

Privacy compliance98.9%of page views loaded the consent manager, up from under 1.5%

The problem
Flex falls under California privacy law (CPRA), so visitors must be able to say no to tracking. The tool that recorded their choice was loading on under 1.5% of production page views, because a feature-flag gate kept it switched off.
What I did
I found the gate and removed it. I also rebuilt the “Do Not Sell” handling on the consent vendor’s own APIs, so one opt-out stopped Google Tag Manager and every vendor pixel.
The result
Coverage went from under 1.5% to 98.9% of page views, checked in Amplitude with no tag-manager errors.
Behind it
It sat on a tracking platform I designed and owned: identity, Amplitude, Transcend Airgap and Google Tag Manager across the Webflow and Unbounce sites, delivered as 8 scripts from a CDN with QA and production switching, pinned integrity hashes and snapshot rollback.
  1. Visitor arrives
  2. Consent manager loads
  3. Visitor chooses
  4. Tags and pixels run only if yes

02 / 06

Finding the 21% of paid-ad visits that analytics never saw

Ad measurement21%of paid-ad visits never reached analytics, measured by a pipeline I built

The problem
Paid-ad arrivals and analytics page views did not line up, and the size of the gap was unclear.
What I did
I built a pipeline that recorded every paid arrival with a beacon on CloudFront, then joined it to Amplitude page views in Athena and Snowflake. The join covered 99.8% of page views, and a query cost about $0.07.
The result
Paid arrivals were 1.26× recorded page views, a gap of about 21%.
Behind it
The goal was not the pipeline. It was knowing how far the dashboard could be trusted.

03 / 06

Rebranding the help center every year, and rebuilding it in 2026

Testing600+automated checks guarded the help center I rebuilt from scratch

The problem
Flex’s Zendesk help center is rebranded every year, and I did all three: 2024, 2025 and 2026. The 2026 one was not a repaint. It needed a ground-up rebuild on Zendesk’s Guide Templating API v4.
What I did
I built 32 templates with esbuild and token-driven CSS, with accessibility first, plus a chat loader that talks to the mobile app through a versioned contract. It was guarded by 328 unit tests and about 300 Playwright checks, and it went live on Oct 16, 2026 through a reviewer-gated deploy with a smoke test and automatic rollback. I also moved deploys to OAuth 2.0 ahead of Zendesk’s API-token sunset.
The result
A support site that is tested like a product and can be rolled back in one step.

  2. Reviewer approves
  3. Deploy
  4. Smoke test
  5. Automatic rollback if it fails

04 / 06

Faster buttons, and A/B tests you can believe

Button speed0.5 sfaster to open the next page after a button click. I removed a wait built into the old tracking

The problem
The old click-tracking script held visitors on the page for a moment after they clicked a main button, so the next page opened late. A/B test counts also looked too high.
What I did
I upgraded Amplitude’s tracking library (its SDK) to a newer version that records button clicks on its own, and compared it with the old script over a week of real traffic: their click counts differed by only 0.15%, so I deleted the old script. The new engagement and error events exposed three hidden production bugs (about 3.3K unhandled errors a day) within an hour. I also fixed A/B test counts that were inflated 1.34–1.56×.
The result
Buttons responded about half a second sooner, and experiment results rested on honest counts.

  2. Amplitude upgraded
  3. Counts differ by 0.15%
  4. Old script deleted

05 / 06

AI agents with a human at the gate

AI automation36 pagesnew pages added to outage monitoring by an AI agent using my audit tool

The problem
Two jobs were repetitive and easy to get wrong: publishing legal documents to the website, and checking which pages the outage monitoring did not watch.
What I did
I created Flex’s internal Claude Code plugin marketplace (manifest checks and AI review in CI, golden-snapshot tests, opt-in installs, CODEOWNERS) and shipped two plugins on it. /legal-ticket turned a Notion ticket into a checked CDN page, a PDF and a deploy runbook. Nothing was written unless a ≥ 0.996 word-accuracy gate passed, and the production upload stayed human-only. /uptime-scope-audit compared the sitemap and the CMS API with the monitoring list and opened a pull request.
The result
The audit’s first run found 64 pages nobody was watching (the sitemap alone misses ~28%). Flex’s infrastructure agent then ran it unattended, and it added 36 pages to the monitoring list.

  2. Plugin builds page
  3. Accuracy gate ≥ 0.996
  4. Human uploads to production

06 / 06

Watching 479 URLs for a few dollars a month

Monitoring cost479 URLsmonitored for under $10 a month (est.), vs $2.2–4.3K on Datadog Synthetics

The problem
Watching this many URLs with Datadog Synthetics would have cost an estimated $2.2–4.3K a month.
What I did
I wrote, on my own, a serverless poller in Python 3.12: AWS Lambda containers on EventBridge Scheduler, with Datadog and PagerDuty for alerts and Terraform across five environments. It paced requests per host so Cloudflare did not block it, had 300+ tests, and a pre-launch audit of the URL list prevented about 40 false alerts on day one.
The result
479 URLs watched for single-digit dollars a month (my estimate), against $2.2–4.3K.

  2. Lambda poller
  3. Datadog
  4. PagerDuty alert

How I work

Three habits behind all of it

  1. 01

    Measure before you trust

    A dashboard is only useful if you know how far to trust it. I measured the paid-traffic gap from raw data and got 21%.

  2. 02

    Automation gets a gate

    Agents do the repetitive work. A check decides whether the result is good enough, and a person still presses the button for anything that reaches production.

  3. 03

    Every change can be undone

    Snapshots, rollbacks and reviewer-gated deploys mean a bad release is a quick revert, not a weekend.
