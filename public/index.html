Six problems, what I did, and what changed

01

The consent manager was missing from almost every page view

Privacy compliance98.9%of page views now load the consent manager, up from under 1.5%

The problem
Flex falls under California privacy law (CPRA), so visitors must be able to say no to tracking. The tool that records their choice was loading on under 1.5% of production page views, because a feature-flag gate kept it switched off.
What I did
I found the gate and removed it. I also rebuilt the “Do Not Sell” handling on the consent vendor’s own APIs, so one opt-out now stops Google Tag Manager and every vendor pixel.
The result
Coverage went from under 1.5% to 98.9% of page views, checked in Amplitude with no tag-manager errors.
Behind it
It sits on a tracking platform I designed and own: identity, Amplitude, Transcend Airgap and Google Tag Manager across the Webflow and Unbounce sites, delivered as 8 scripts from a CDN with QA and production switching, pinned integrity hashes and snapshot rollback.
  1. Visitor arrives
  2. Consent manager loads
  3. Visitor chooses
  4. Tags and pixels run only if yes

02

Finding the 21% of paid-ad visits that analytics never saw

Ad measurement21%of paid-ad visits never reached analytics, measured by a pipeline I built

The problem
Paid-ad arrivals and analytics page views did not line up. An early estimate put the gap at 45–52%, a number worth checking before anyone acted on it.
What I did
I built a pipeline that records every paid arrival with a beacon on CloudFront, then joins it to Amplitude page views in Athena and Snowflake. The join covered 99.8% of page views, and a query costs about $0.07.
The result
Paid arrivals were 1.26× recorded page views, a gap of about 21%. The earlier 45–52% figure was wrong, so I corrected it and said so.
Behind it
The goal was not the pipeline. It was knowing how far the dashboard could be trusted.

03

Rebranding the help center every year, and rebuilding it this year

Testing600+automated checks guard the help center I rebuilt from scratch

The problem
Flex’s Zendesk help center is rebranded every year, and I did all three: 2024, 2025 and this year. This year’s was not a repaint. It needed a ground-up rebuild on Zendesk’s Guide Templating API v4.
What I did
I built 32 templates with esbuild and token-driven CSS, with accessibility first, plus a chat loader that talks to the mobile app through a versioned contract. It is guarded by 328 unit tests and about 300 Playwright checks, and it went live on Oct 16, 2026 through a reviewer-gated deploy with a smoke test and automatic rollback. I also moved deploys to OAuth 2.0 ahead of Zendesk’s API-token sunset.
The result
A support site that is tested like a product and can be rolled back in one step.

04

Faster buttons, and A/B tests you can believe

Click speed0.5 sless wait after each button click, because I removed a pause in the old tracking code

The problem
The old click-tracking code paused every button click before the visitor moved on. A/B test exposure counts also looked too high.
What I did
I moved click tracking to Amplitude autocapture (SDK 2.7 to 2.45) and reconciled it to within 0.15% of the old events before deleting the old layer. The new engagement and error events exposed three hidden production defects (about 3.3K unhandled errors a day) within an hour. I also fixed A/B exposure counts that were inflated 1.34–1.56×.
The result
Buttons respond about half a second sooner, and experiment results rest on honest counts.

  2. Autocapture
  3. Reconciled to 0.15%
  4. Old layer deleted

05

AI agents with a human at the gate

AI automation36 pagesnew pages added to outage monitoring by an AI agent using my audit tool

The problem
Two jobs were repetitive and easy to get wrong: publishing legal documents to the website, and checking which pages the outage monitoring does not watch.
What I did
I created Flex’s internal Claude Code plugin marketplace (manifest checks and AI review in CI, golden-snapshot tests, opt-in installs, CODEOWNERS) and shipped two plugins on it. /legal-ticket turns a Notion ticket into a checked CDN page, a PDF and a deploy runbook. Nothing is written unless a ≥ 0.996 word-accuracy gate passes, and the production upload stays human-only. /uptime-scope-audit compares the sitemap and the CMS API with the monitoring list and opens a pull request.
The result
The audit’s first run found 64 pages nobody was watching (the sitemap alone misses ~28%). Flex’s infrastructure agent now runs it unattended, and it has added 36 pages to the monitoring list so far.

  2. Plugin builds page
  3. Accuracy gate ≥ 0.996
  4. Human uploads to production

06

Watching 479 URLs for a few dollars a month

Monitoring cost479 URLsmonitored for under $10 a month (est.), vs $2.2–4.3K on Datadog Synthetics

The problem
Watching this many URLs with Datadog Synthetics would have cost an estimated $2.2–4.3K a month.
What I did
I wrote, on my own, a serverless poller in Python 3.12: AWS Lambda containers on EventBridge Scheduler, with Datadog and PagerDuty for alerts and Terraform across five environments. It paces requests per host so Cloudflare does not block it, has 300+ tests, and a pre-launch audit of the URL list prevented about 40 false alerts on day one.
The result
479 URLs watched for single-digit dollars a month (my estimate), against $2.2–4.3K.

How I work

Three habits behind all of it

  1. i

    Measure before you trust

    My first estimate of missing paid traffic was wrong. I measured it properly, got 21%, and replaced the old number everywhere.

  2. ii

    Automation gets a gate

    Agents do the repetitive work. A check decides whether the result is good enough, and a person still presses the button for anything that reaches production.

  3. iii

    Every change can be undone

    Snapshots, rollbacks and reviewer-gated deploys mean a bad release is a quick revert, not a weekend.
